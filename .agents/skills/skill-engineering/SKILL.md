# Навыки агентов проекта

Навык ведёт создание, приём и изменение навыков в `.agents/skills/`. Навык — методика для агента: что прочитать, какие шаги пройти и как проверить результат. Факты и решения живут в документах и ADR, навык на них ссылается. Роль: Skill Engineer.

Агент для нового навыка оформляется по `agent-engineering`, оценка навыка — по `agent-evaluation`.

## Прочитай сначала

- [docs/agents.md](../../../docs/agents.md) — роли со статусом «ждёт навыков» и столбец «Нужны навыки»; [порядок добавления агента](../../../docs/agents.md#как-добавить-или-изменить-агента).
- [AGENTS.md](../../../AGENTS.md) — таблица навыков и правила, которые навык не может ослабить.
- [CONTRIBUTING.md](../../../CONTRIBUTING.md#документация) — правила документации: один факт в одном месте, относительные ссылки.
- Образцы навыков репозитория: `.agents/skills/task-execution/SKILL.md`, `.agents/skills/independent-security-review/SKILL.md`.
- [skills-lock.json](../../../skills-lock.json) — сторонние навыки с источником, коммитом и хешем папки ([алгоритм хеша](references/external-intake.md#хеш-папки-навыка)); [scripts/link-agent-skills.mjs](../../../scripts/link-agent-skills.mjs) — ссылки для Claude Code.
- Приём стороннего навыка: [references/external-intake.md](references/external-intake.md).

## Шаги

1. **Потребность.** Навык нужен, когда роль из реестра «ждёт навыков» или у агента есть пробел в столбце «Чего не хватает». Несколько мелких названий из реестра объединяются в один глубокий навык по зоне.
   Готово, когда названы роли и агенты, которые получат навык, и его граница с соседними навыками.
2. **Источник.** Сначала существующие навыки репозитория — расширить лучше, чем создать новый. Сторонний навык рассматривается только через приём из [references](references/external-intake.md). Своя методика пишется по документам и ADR репозитория.
   Готово, когда выбран путь: расширение, сторонний как есть, адаптация или свой.
3. **Структура.** Папка `.agents/skills/<имя>/` с `SKILL.md`, детали — в `references/`, вспомогательные скрипты — в `scripts/`. `SKILL.md`: frontmatter `name` и `description`; заголовок и назначение; «Прочитай сначала» со ссылками на канонические документы и ADR; нумерованные «Шаги», у каждого «Готово, когда …» и при необходимости **Правило** со ссылкой; «Проверки» чек-листом; «Вне области» со ссылками на соседние навыки. Объём `SKILL.md` — до ~150 строк.
   Готово, когда у каждого шага есть проверяемый критерий завершения.
4. **Описание.** `description` — одна строка, триггер выбора навыка: что делает и когда применять, ключевые термины проекта и английские ключевые слова в скобках. Имя навыка — короткое, в kebab-case, по зоне, а не по роли или инструменту; совпадает с именем папки.
   Готово, когда по `description` навык отличим от соседних.
5. **Содержание.** Текст на русском, термины по [глоссарию](../../../docs/glossary.md), ссылки только относительные и внутри репозитория. Ссылкой оформляются только файлы, которые точно есть в репозитории; документ, который есть не в каждом проекте, упоминается как путь в `inline code` с оговоркой «если есть». Числа, статусы и правила — ссылкой на канонический документ, не копией. Решение, которого нет в документах, навык не придумывает — пишет «вопрос владельцу». Без «compliant» и «certified». В адаптированном навыке нет упоминаний источника и автора.
   Готово, когда `grep` по навыку не находит копий чисел из документов и упоминаний внешних авторов.
6. **Проверка.** Эталонные задачи прогоняются с навыком и без него по `agent-evaluation`; навык проверяет независимый ревьюер, для безопасности — `independent-security-review`; одобряет владелец.
   Готово, когда отчёт оценки показывает выигрыш на эталонах и замечания ревью закрыты.
7. **Регистрация.** `npm run agents:check` ([скрипт](../../../scripts/sync-agents.mjs)) проверяет канон агентов и навыки: однострочные `name` и `description` агента (без `>` и `|`), `name` совпадает с именем файла, навыки агента существуют, имя агента в обратных кавычках есть в `docs/agents.md`, тело без `'''`; у каждого навыка в `.agents/skills/` `name` совпадает с именем папки, `description` не пуст, относительные ссылки в `SKILL.md` и `references/` существуют; навык, который не использует ни один агент, — ошибка. `npm run check:docs` проверяет ссылки в документах и в `.agents/` не смотрит, поэтому для навыков опирайся на `agents:check`. Порядок: `npm run skills:link`; навык в таблице навыков `AGENTS.md`; агент — по `agent-engineering`; строки ролей в `docs/agents.md`; `npm run check:docs`.
   Готово, когда `npm run check:docs` и `npm run agents:check` проходят, а роль больше не «ждёт навыков».

## Проверки

- [ ] Frontmatter содержит `name`, совпадающий с именем папки, и однострочный `description`.
- [ ] Все ссылки относительные и ведут на существующие файлы репозитория.
- [ ] Нет копий чисел, таблиц и правил из канонических документов.
- [ ] Сторонний навык записан в `skills-lock.json` с источником, путём, коммитом и хешем; его скрипты и хуки просмотрены, ничего не запускалось при приёме. Навык в `.agents/skills/` без записи в `skills-lock.json` и не написанный в репозитории — вопрос владельцу.
- [ ] Сторонний навык под MIT, Apache-2.0 и похожими лицензиями скопирован «как есть» вместе с файлом лицензии или notice, если он есть в источнике.
- [ ] Адаптированный навык переписан своими словами, без источника и автора.
- [ ] Навык назначен хотя бы одному агенту; неиспользуемых навыков нет.
- [ ] Изменения навыков авторизации, обработки персональных данных и безопасности прошли независимую проверку.

## Вне области

- Профили агентов и оркестрация — `agent-engineering`.
- Эталонные задачи, метрики и стоимость — `agent-evaluation`.
- Правила документации — `documentation`.
