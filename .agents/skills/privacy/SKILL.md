# Приватность

Навык проверяет, что изменение собирает только нужные персональные данные, показывает их только тем, кому положено, и в маскированном виде, не выносит их в журналы и аналитику и экспортирует только с подтверждением. Основания обработки, сроки хранения, порядок ответа на запросы субъектов и применимое право определяют владелец продукта и юрист: навык фиксирует, что описано в документах проекта, а остальное выводит вопросом. Агент не даёт юридических заключений.

## Прочитай сначала

- Спецификация задачи (навык `product-requirements`) — какое действие требует каждого поля.
- Реестр или модель данных, если в проекте есть (например `docs/data-model.md`), — где хранятся персональные данные и кто их владелец.
- [Реестр ADR](../../../docs/adr/README.md) — решения о доступе, изоляции арендаторов, хранении, журналировании и аутентификации.
- [Глоссарий](../../../docs/glossary.md) — термины проекта.
- Соседние навыки: прочитай `SKILL.md` навыков `independent-security-review` (секреты, журналы, доступ) и `threat-modeling` (раскрытие данных как угроза).

## Шаги

1. **Карта данных изменения.** Перечисли новые и изменённые поля с персональными данными (имя, контакты, идентификаторы, IP, геолокация, платёжные и биометрические данные, свободный текст от пользователя), их источник, модуль, хранилище и получателей (внутренние сервисы, внешние обработчики).
   Готово, когда каждое поле имеет источник, место хранения, получателей и строку в реестре данных проекта или запись «реестра нет — вопрос владельцу».
2. **Минимизация.** Поле нужно для описанного в спецификации действия; иначе — вопрос владельцу продукта до реализации. Предпочитай производные значения (флаг, возрастная группа) исходным.
   Готово, когда для каждого нового поля указан пункт спецификации, который его требует.
3. **Доступ по области и роли.** Чтение персональных данных — только в своей области (арендатор, организация) и с правом роли; чужой ресурс — `404`.
   Готово, когда для каждого нового маршрута чтения есть тест «другая область → `404`» и, если изоляция поддерживается хранилищем, «без области → 0 строк».
4. **Маскирование и подтверждение.** В интерфейсах персонала контакты и идентификаторы показываются маскированными по умолчанию; раскрытие полного значения и экспорт — отдельным правом, с повторным подтверждением входа, если оно предусмотрено, и с записью в аудит. Конкретные правила маски не утверждены — вопрос владельцу, а не выбор агента.
   Готово, когда каждый экран и экспорт с персональными данными указан с правом, маской или ссылкой на открытый вопрос.
5. **Журналы, события, аналитика.** Персональных данных нет в журналах, трассировках, метриках, событиях для аналитики, сообщениях об ошибках, URL и параметрах запросов; во внешние сервисы (мониторинг, аналитика, LLM-провайдеры) уходит только то, что разрешено документом.
   Готово, когда сериализаторы журналов и полезная нагрузка событий в diff проверены, а для них есть тест или запись «нет теста».
6. **Запросы субъекта данных.** Доступ, исправление, выгрузка и удаление — только по описанному в проекте процессу. Если процесса нет, изменение не придумывает его: сроки ответа, состав выгрузки и правила удаления — вопрос владельцу и юристу. Удаление учитывает копии: резервные копии, кеши, поисковые индексы, внешние обработчики.
   Готово, когда изменение не обходит описанный процесс, а неописанные шаги перечислены вопросами.
7. **Сроки хранения.** Только из документа проекта; иначе «не определён, вопрос владельцу». Тестовые данные и фикстуры — синтетические, без реальных персональных данных.
   Готово, когда в изменении нет срока хранения без источника и нет реальных персональных данных в репозитории.

## Проверки

- [ ] Каждое новое поле с персональными данными обосновано спецификацией и внесено в реестр данных или вынесено вопросом.
- [ ] Тесты области для маршрутов чтения персональных данных есть.
- [ ] Раскрытие и экспорт — отдельное право и запись в аудит.
- [ ] Журналы, события, ошибки и внешние сервисы без персональных данных сверх разрешённого.
- [ ] Ни одно правило маскирования, срок хранения или порядок ответа на запрос не придуман агентом.
- [ ] В репозитории и фикстурах нет реальных персональных данных.
- [ ] Нет слов «compliant» и «certified»; юридические вопросы помечены «требует подтверждения юристом».

## Вне области

- Юридическая оценка, основания обработки и применимое право — юрист (человек); агент только формулирует вопросы.
- Секреты, аутентификация, авторизация — `independent-security-review`.
- Модель угроз — `threat-modeling`.
- Схема хранилища и миграции — исполнитель задачи по навыку `task-execution`.
