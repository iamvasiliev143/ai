# Каталог сценариев и отчёт тестирования

Каталог — общие сценарии. Проект дополняет его своими (например сценариями своих инвариантов) с собственными префиксами ID; номера не переиспользуются.

## Конкуренция, идемпотентность и сбои

| ID | Сценарий | Уровень | Ожидание |
| --- | --- | --- | --- |
| C-01 | Два одинаковых запроса параллельно, один ключ идемпотентности | Интеграционный | Один результат записан, второй ответ — сохранённый результат |
| C-02 | Тот же ключ, другое тело | e2e + интеграционный | Ошибка конфликта, новой записи нет |
| C-03 | Гонка двух операций над одним ресурсом | Интеграционный | Нет взаимной блокировки, инвариант ресурса сохранён |
| C-04 | Ошибка после записи до фиксации транзакции | Интеграционный | Нет частичных записей, побочных событий и задач |
| C-05 | Таймаут ожидания блокировки | Интеграционный | Временная ошибка, повтор тем же ключом без дубля |
| C-06 | Повтор операции, которая ещё выполняется | Интеграционный | Явный статус «в обработке», а не таймаут или дубль |
| C-07 | Повторная отмена той же операции | Интеграционный | Вторая отмена ничего не меняет |
| C-08 | Изменение неизменяемой записи (журнал, аудит) под ролью приложения | Интеграционный | Отклонено |

## Доступ и данные

| ID | Сценарий | Уровень | Ожидание |
| --- | --- | --- | --- |
| A-01 | Запрос без контекста доступа | Интеграционный | Нет данных |
| A-02 | Ресурс другого владельца | e2e | `404` (или принятый код) |
| A-03 | Самоподтверждение чувствительной команды | e2e | Отклонено |
| A-04 | Чувствительная команда без требуемого подтверждения | e2e | Не исполнена |
| A-05 | Пользователь без нужной роли или без повторной аутентификации | e2e | Отказ |

## Внешние интеграции

| ID | Сценарий | Уровень | Ожидание |
| --- | --- | --- | --- |
| E-01 | Повтор входящего уведомления (вебхука) | e2e | Обработано один раз |
| E-02 | Уведомления не по порядку | e2e | Только допустимые переходы состояния |
| E-03 | Неверная подпись или просроченная метка времени | e2e | Отказ, событие в журнале безопасности |
| E-04 | Таймаут и потеря ответа внешней системы | e2e | Неизвестный исход разбирается сверкой или повтором, без двойной операции |

ID сценариев внешнего контракта берутся из самого контракта и не перенумеровываются.

## Шаблон отчёта

```markdown
# Отчёт тестирования: <задача>

Сборка: <sha> · Среда: <локально | тестовая> · Дата: <дата>

| Требование | Строка матрицы | Тест | Результат |
| --- | --- | --- | --- |
| <ID и ссылка> | <ID строки или —> | <файл:тест> | прошёл / упал / не проверяем: <причина> |

## Команды
<npm run check — итог>

## Дефекты
1. <кратко> — шаги: <…>; ожидание: <…>; факт: <…>; владелец: <роль>.

## Открытые вопросы
- <инструмент, данные, среда>
```
