# Документация проекта

Навык ведёт правку документов в `docs/` и корневых `*.md` так, чтобы каждый факт жил в одном месте, термины совпадали с глоссарием, а ссылки и индекс ADR оставались целыми. Выбор архитектурного решения принимает владелец: навык оформляет решение, а не придумывает его. Роль: Technical Writer.

При работе с ADR и глоссарием правила этого репозитория приоритетнее глобальных и сторонних навыков.

## Прочитай сначала

- [CONTRIBUTING.md](../../../CONTRIBUTING.md#документация) — один факт в одном документе, канонические источники, статусы, примеры.
- [docs/README.md](../../../docs/README.md) — оглавление и разделы.
- [docs/adr/README.md](../../../docs/adr/README.md) — правила ADR, индекс, шаблон.
- [docs/glossary.md](../../../docs/glossary.md) — термины и раздел [«Устаревшие синонимы»](../../../docs/glossary.md#устаревшие-синонимы).

## Шаги

1. **Найди канонический документ.** ADR — канон для решений; глоссарий — для терминов; спецификации и контракты API — для таблиц, статусов и маршрутов; трекеры — для статусов работ. Где что лежит, видно по оглавлению `docs/README.md`. Поиск по ключевым словам: `grep -rn "<термин>" docs/`.
   Готово, когда назван один файл, куда вносится факт, а остальные упоминания станут ссылками на него.
2. **Термины.** Каждое новое понятие сначала добавь в глоссарий (алфавитный порядок, колонка «Где подробнее»). Слова из «Устаревших синонимов» заменяй на канонические.
   Готово, когда `grep` по устаревшим синонимам в изменённых файлах пуст, а новый термин есть в глоссарии.
3. **ADR.** Новый файл `docs/adr/NNNN-краткое-имя.md` со следующим свободным номером по шаблону из `docs/adr/README.md`. Принятый ADR не переписывается: в старом меняется только статус на `superseded` и ссылка, либо добавляется строка «Уточнён: [ADR NNNN]» / «Частично заменён: [ADR NNNN]» под датой; в новом — «Уточняет: [NNNN]» / «Частично заменяет: [NNNN]». Новый ADR добавь в индекс. Содержание решения — по `architecture-decisions`.
   Готово, когда diff принятого ADR содержит только статус, строку связи или исправление опечатки и битой ссылки.
4. **Новый документ.** Добавь его в оглавление `docs/README.md` в подходящий раздел (или в родительский документ, если это шаблон или пример). Статус пиши нейтрально: «Статус: проект спецификации, реализация не начата».
   Готово, когда `npm run check:docs` не сообщает «нет входящих ссылок».
5. **Шаблоны и примеры.** Шаблон лежит рядом с документом, который его требует; заполненный пример — отдельным файлом, не больше одного примера на сценарий, первая строка — «Учебный пример, вымышленные данные», идентификаторы с меткой `-EX-`, без реальных персональных данных, секретов и внутренних адресов.
   Готово, когда первая строка примера совпадает дословно.
6. **Ссылки.** Только относительные и только внутри репозитория. Внешние системы и соседние репозитории описываются как интеграции по версионируемому контракту — без ссылок на файлы другого репозитория и без абсолютных путей.
   Готово, когда `npm run check:docs` завершается с кодом 0.
7. **Статусы и доказательства.** Фактические результаты, допуски и подписи пишутся только в трекерах и протоколах по доказательствам. Формулировка результата — «соответствует документу X» или «требует подтверждения владельцем / специалистом»; слова «compliant» и «certified» не используем.
   Готово, когда каждое утверждение о результате ссылается на доказательство или помечено как требующее подтверждения.

## Проверки

- [ ] `npm run check:docs` — 0 проблем: ссылки, якоря, выход за репозиторий, документы без входящих ссылок, нумерация ADR.
- [ ] Индекс в `docs/adr/README.md` содержит каждый файл ADR с правильным статусом (сверка списка файлов `ls docs/adr` с таблицей индекса).
- [ ] Число, таблица, статус или маршрут API не продублированы в неканоническом документе — на их месте ссылка (ручная проверка по `grep` значения).
- [ ] Новые термины есть в глоссарии; устаревших синонимов в изменённых файлах нет.
- [ ] Принятые ADR изменены только в допустимых местах (по `git diff`).
- [ ] В тексте нет ссылок на файлы другого репозитория и абсолютных путей.
- [ ] В примерах нет реальных персональных данных, секретов и внутренних адресов.

## Скрипт

[scripts/check-links.mjs](scripts/check-links.mjs) (Node, без зависимостей) запускается как `npm run check:docs`. Обходит все `.md` репозитория, кроме `node_modules`, `.agents`, `.claude`, `.codex`, `dist`, `build`, `.git`, `coverage`, `.idea`, `.vscode`. Проверяет относительные ссылки и якоря, выход за пределы репозитория, входящие ссылки на каждый `docs/**/*.md` и нумерацию ADR. Ссылки внутри блоков кода и `inline code` пропускает, внешние ссылки (`https:` и т. п.) не проверяет. Код выхода 1 при любой проблеме.

## Вне области

- Содержание архитектурных решений — `architecture-decisions`; требования — `product-requirements`.
- Код приложений и тесты — `task-execution`, `test-strategy`.
- Агенты и навыки в `.agents/` — `agent-engineering`, `skill-engineering`; их ссылки проверяет `npm run agents:check`.
- Юридическая оценка — юрист владельца; в документе такие места помечаются «требует подтверждения юристом».
