# Шаблоны архитектурной работы

Шаблон самого ADR — в `docs/adr/README.md`. Здесь — RFC и отчёт ревью.

## RFC

```markdown
# RFC: <вопрос>

Автор: <роль>. Статус: черновик | на обсуждении | решено.
Затронутые ADR: <ссылки>.

## Вопрос и срочность
Что нужно решить и что сломается без решения.

## Ограничения
- Инвариант или требование — ссылка на источник.

## Варианты
| Ось | Вариант A | Вариант B | Ничего не менять |
| --- | --- | --- | --- |
| Корректность и инварианты | | | |
| Безопасность и изоляция данных | | | |
| Производительность (замер или план замера) | | | |
| Стоимость | | | |
| Эксплуатация | | | |
| Сложность и сопровождение | | | |
| Обратимость | | | |

## Консультации
Роль — замечание — как учтено.

## Решение
Вариант, автор решения, дата. Ссылка на ADR.
```

## Отчёт ревью против ADR

```markdown
## Ревью <объект> против ADR

| ADR | Вердикт | Расхождение (файл:строка) | Последствие | Что делать |
| --- | --- | --- | --- | --- |
| 0003 | соответствует | — | — | — |
| 0007 | расхождение | src/...:42 | | исправить код / новый ADR |

Открытые вопросы владельцу: ...
```

## Частые расхождения

| Признак в коде | Что под угрозой |
| --- | --- |
| Сетевой вызов внутри транзакции базы | Конкурентный доступ, время блокировок, согласованность |
| Прямой импорт внутренностей чужого модуля | Границы модулей |
| Новый брокер, кеш или очередь без ADR | Принятый стек и эксплуатация |
| Бизнес-правило или настройка окружения константой в коде | Конфигурируемость, переносимость |
| Зависимость добавлена без обоснования | Принятый стек, безопасность цепочки поставок |
| Запрос к данным без проверки владельца или области доступа | Изоляция данных |
