# Планирование и исполнение работ

Навык превращает принятую спецификацию или ADR в граф задач, которые агенты и люди могут взять без уточнений, и ведёт их до релиза. Он не меняет требования и архитектуру: расхождение возвращается владельцу спецификации или архитектору. Релиз в продакшен одобряет человек.

## Шаги

1. **Вход.** Возьми принятую спецификацию, ADR или дефект. Если входа нет или он противоречит документам — задача остаётся в анализе, вопрос владельцу.
   Готово, когда у работы есть ссылка на принятый вход и его владелец.
2. **Вертикальная декомпозиция.** Режь работу на задачи с проверяемым результатом от интерфейса до теста: «регистрация по email с подтверждением», а не «таблица пользователей». Первая задача — сквозная тонкая нить, остальные наращивают её.
   **Правило:** одна задача — один агент-владелец из [таблицы агентов](../../../docs/agents.md#агенты) и одна зона файлов. Задача, которой нужны два агента, делится.
   Готово, когда каждую задачу можно сдать и проверить отдельно.
3. **Карточка задачи (Definition of Ready).** Владелец, разрешённые файлы, вход (спецификация, ADR, версия контракта), критерии «Готово, когда», обязательные проверки и независимые ревьюеры. Изменения, затрагивающие [инварианты](../../../AGENTS.md#инварианты), авторизацию, секреты, персональные данные и внешние интеграции, всегда получают независимого ревьюера (`code-reviewer`, `security-reviewer`, при персональных данных — `privacy-specialist`).
   Готово, когда карточка заполнена по шаблону и задача переходит в состояние готовности.
   **Правило:** карточки, граф и статус-отчёты не дублируют документы. Задачи можно вести в GitHub Issues/Projects или в Notion — выбор и место фиксирует проект; карточка ссылается на документы, а не копирует их.
4. **Граф зависимостей.** Блокирующие и разблокируемые задачи, включая внешние: доступ, договорённость, решение заказчика. Внешняя зависимость имеет адресата и срок, а не только пометку «ждём».
   **Правило:** две задачи не меняют одни и те же файлы одновременно; контракт между частями системы согласуется до параллельной работы.
   Готово, когда в графе нет циклов, критический путь назван, внешние зависимости отмечены.
5. **Исполнение.** Веди [состояния задачи](../../../docs/agents.md#состояния-задачи). Блокировка — с причиной и адресатом; запрос изменений возвращает задачу исполнителю; завершение — только с доказательствами проверок.
   Готово, когда у каждой задачи в работе есть состояние, владелец и дата последнего изменения.
6. **Статус-отчёт.** Сделано с доказательствами, в работе, блокеры с адресатами, риски для релиза, решения, нужные от людей.
   Готово, когда все поля шаблона статус-отчёта заполнены и каждый блокер имеет адресата.
7. **Эскалация.** Блокер уходит к владельцу решения: по продукту — `product-manager`, по архитектуре — `architect`, нерешённое — к человеку. Срок, после которого блокер эскалируется, задаёт проект; если не задан — вопрос владельцу.
   Готово, когда эскалация содержит факты, варианты и нужное решение.
8. **Релиз.** Состав релиза, совместимость миграций и конфигурации назад, порядок отката, закрытые критерии приёмки, независимые отчёты. Подготовка и выкатка — навык `release-delivery`. Агенты не выполняют поставку в продакшен без одобрения человека.
   Готово, когда чек-лист релиза заполнен и одобрение человека записано.

## Проверки

- [ ] Каждая задача имеет одного владельца, разрешённые файлы, вход и критерии.
- [ ] Изменения инвариантов, доступа, секретов и персональных данных имеют независимых ревьюеров.
- [ ] Граф без циклов, критический путь и внешние зависимости с адресатами.
- [ ] Завершение подтверждено командами проверок (`npm run check`, при правке документации `npm run check:docs`) и их итогом.
- [ ] Карточки и отчёты ссылаются на документы, а не копируют их.
- [ ] Релиз: состав, порядок отката, совместимость, одобрение человека.

## Вне области

- Содержание требований — `product-requirements`; архитектура — `architecture-decisions`.
- Реализация задачи — `task-execution`; выкатка и откат — `release-delivery`.
- Эксплуатация после релиза — `operations`.
