# Шаблоны планирования

## Карточка задачи

```markdown
# <ID>. <Результат одной фразой>

Состояние: <по docs/agents.md, раздел «Состояния задачи»>
Владелец (агент): <имя из docs/agents.md>. Ответственный человек: <роль>.
Вход: <спецификация, ADR, версия контракта>.
Строка матрицы приёмки: <номер, если в проекте есть матрица>.

## Разрешённые файлы
- src/<модуль>/**

## Готово, когда
- <наблюдаемый результат> — среда — доказательство.

## Проверки
- npm run check
- npm run check:docs (если менялась документация)
- npm run agents:check (если менялись агенты или навыки)

## Независимое ревью
code-reviewer; security-reviewer (авторизация, секреты, внешние интеграции, инварианты); privacy-specialist (персональные данные).

## Зависимости
Блокируется: <ID или внешнее: доступ, договорённость, решение — адресат, срок>. Разблокирует: <ID>.
```

Карточку можно завести как GitHub Issue (поля — разделы тела, состояние — колонка в GitHub Projects) или как страницу в базе Notion (поля — свойства). Формат выбирает проект.

## Граф зависимостей

```text
T-1 → T-2   (контракт API до параллельной работы клиента, сервера и тестов)
EXT: доступ к тестовой среде партнёра (адресат, срок) → T-5
Критический путь: T-1 → T-2 → T-5
```

## Статус-отчёт

```markdown
## Статус <дата>

Сделано: <ID> — доказательство.
В работе: <ID> — состояние, владелец.
Блокеры: <ID> — причина — кому — нужное решение.
Риски для релиза: <риск> — влияние — что делаем.
Решения от людей: <вопрос> — к кому — срок.
```

## Чек-лист релиза

- [ ] Состав релиза: артефакты сборки, миграции, конфигурация, изменения регламентов.
- [ ] Миграции и конфигурация совместимы назад, порядок отката описан и проверен.
- [ ] Критерии приёмки, которые закрывает релиз, имеют доказательства по средам.
- [ ] Независимые отчёты: ревью кода, проверка безопасности (если затронута).
- [ ] Заметки к релизу и документация обновлены.
- [ ] Решение о выпуске принято человеком и записано.
