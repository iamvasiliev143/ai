# Оценка агентов и навыков

Навык ведёт проверку того, что навык или агент действительно улучшает результат, и учёт стоимости прогонов. Оценка идёт по критериям приёмки задачи и проверкам навыка, а не по впечатлению. Роли: AI Evaluation Engineer, AI Cost Optimizer.

Создание навыков — `skill-engineering`, профили и оркестрация агентов — `agent-engineering`.

## Шаги

1. **Эталонные задачи.** На навык или агента — 3–5 задач из его зоны: типичная, граничная и задача-ловушка, где лёгкий путь нарушает инвариант из `AGENTS.md` или ADR (например, секрет в коде или логе, «прочитать, потом записать» без защиты от гонки, ответ об успехе до фиксации результата, тест, подогнанный под ошибку). У каждой задачи: вход, разрешённые файлы, критерии приёмки, ожидаемые артефакты.
   Готово, когда каждый критерий проверяется командой, тестом или ссылкой на строку документа.
2. **Хранение эталонов.** Место хранения выбирает владелец (например, `.agents/evals/` или раздел в `docs/`); если решения нет — это вопрос владельцу, а эталоны прикладываются к отчёту оценки.
   Готово, когда место хранения записано в отчёте как решение владельца или открытый вопрос.
3. **Прогон.** Каждая задача прогоняется дважды: с навыком (или агентом) и без него — базовая линия: для навыка — тот же агент без этого навыка в `skills`; для агента — общий агент без профиля с той же задачей и теми же разрешёнными файлами; на одной модели, в отдельном worktree, с чистым контекстом. Повторы — не больше лимита из [правил](../../../docs/agents.md#правила-и-полномочия).
   Готово, когда для каждой пары есть артефакты и вывод команд проверок.
4. **Оценка.** По каждому критерию: выполнен, не выполнен, нарушен инвариант. Нарушение инварианта — провал задачи. Оценивает независимый ревьюер, не автор навыка.
   **Правило:** «стало лучше» — только если навык выигрывает по критериям хотя бы на одной задаче и не проигрывает ни на одной.
   Готово, когда таблица результатов заполнена для обоих прогонов.
5. **Разбор ошибок.** Для каждого провала — причина: навык (нет шага или неверное правило), контекст (не загружен документ), модель, инструмент или процесс (задача без критериев, неверное разбиение). Исправляется причина, а не симптом.
   Готово, когда у каждого провала названа причина и предложено исправление с владельцем.
6. **Регрессия.** Изменение навыка или агента повторяет прогон его эталонов. Изменение, которое ломает прежде пройденную задачу, не принимается без решения владельца.
   Готово, когда результаты до и после изменения приложены к PR навыка.
7. **Грейд.** Грейд роли в реестре подтверждается результатами: Middle — задачи по спецификации, Senior — граничные задачи и задачи-ловушки без нарушений. Название модели грейд не подтверждает.
   Готово, когда предложение по грейду опирается на таблицу результатов.
8. **Стоимость.** Claude Code поддерживает у агента поля `model` и `effort`, но канон агентов их не переносит: [скрипт генерации](../../../scripts/sync-agents.mjs) пишет только `name`, `description`, `skills` и запрет правки для ревьюеров. Задать модель или effort по роли можно только изменением скрипта, с одобрения владельца; выбор значений — тоже решение владельца, навык готовит сравнение. Контекст сокращается ссылками вместо копий и чтением `references/` по необходимости. В отчёте — только измеренные затраты из инструмента запуска; оценок «на глаз» нет.
   Готово, когда отчёт о стоимости содержит измеренные значения или явно пишет «не измерено».

## Проверки

- [ ] У каждой эталонной задачи есть проверяемые критерии и задача-ловушка на инвариант.
- [ ] Данные в эталонах синтетические: без секретов и реальных персональных данных.
- [ ] Прогоны с навыком и без идут на одной модели и в чистом контексте.
- [ ] Оценивает не автор навыка.
- [ ] Каждый провал имеет причину из пяти категорий.
- [ ] Регрессия прогнана при изменении навыка или агента.
- [ ] Цифры стоимости измерены, а не придуманы; выбор модели и effort оставлен владельцу.
