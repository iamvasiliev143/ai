## Каталог STRIDE по границам

| Граница | Угроза (STRIDE) | Пример | Где искать меру |
| --- | --- | --- | --- |
| Клиент → API | Подмена | Кража сессии, CSRF на изменяющей команде | ADR об аутентификации и сессиях |
| | Раскрытие | Токен внутреннего сервиса или лишние данные в ответе | Токены остаются на сервере, схемы ответов |
| | Отказ в обслуживании | Перебор кодов, массовая регистрация, тяжёлые запросы | Лимиты частоты и размера, пагинация |
| Администратор → панель управления | Подмена | Вход без второго фактора, повтор сессии | ADR о входе персонала |
| | Повышение прав | Действие вне своей области, самоутверждение | Модель ролей и областей, разделение обязанностей |
| | Отказ от действия | Нет следа привилегированного изменения | Аудит в той же транзакции |
| Внешний сервис → вебхук | Подмена | Запрос без подписи или с чужим ключом | Подпись по сырому телу, ротация ключей |
| | Изменение | Повтор или переупорядочивание уведомлений | Окно времени, одноразовый ID, идемпотентность |
| Система → внешний API | Подмена адреса | SSRF через адрес из запроса или редирект | Адрес только из утверждённой конфигурации |
| | Раскрытие | Ключ API в журналах или ошибках | Хранилище секретов, фильтр журналов |
| Сервис → хранилище | Раскрытие | Запрос без области видит чужие строки | Изоляция арендаторов в коде и хранилище |
| | Изменение | Изменение или удаление журнала аудита | Права роли приложения, неизменяемость |
| CI и цепочка поставки → среда | Изменение | Скомпрометированная зависимость или действие CI | Lockfile, закрепление версий, аудит зависимостей |
| | Повышение прав | Секрет развёртывания доступен из ветки с недоверенным кодом | Разделение секретов по средам и событиям CI |

## Деревья атак (заготовки)

```text
Цель: доступ к данным другого арендатора
├─ Подставить чужой ID в параметр запроса → мера: область из учётных данных, 404 на чужой ресурс
├─ Запрос без области через фоновую задачу → мера: задача несёт область, тест «без области → 0 строк»
└─ Утечка области через пул соединений → мера: область в пределах транзакции

Цель: повышение прав до администратора
├─ Самоназначение роли → мера: смена прав только другим администратором, аудит
├─ Кража сессии администратора → мера: второй фактор, короткие сессии, step-up
└─ Скомпрометированная зависимость → мера: lockfile, аудит, минимум прав процесса
```
