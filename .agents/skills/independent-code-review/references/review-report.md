# Отчёт ревью и шкала серьёзности

## Шкала

| Уровень | Когда | Что делает автор |
| --- | --- | --- |
| Блокер | Нарушен инвариант `AGENTS.md` или ADR; возможна потеря или порча данных, доступ к чужим данным, секрет в коде; не выполнен критерий приёмки; тесты падают | Исправляет до слияния |
| Важно | Реальный сценарий отказа вне инвариантов: необработанная ошибка внешней системы, гонка без порчи данных, нет теста на новое поведение, документ расходится с кодом | Исправляет или записывает решение владельца |
| Пожелание | Читаемость, имена, мелкие упрощения; замечание без сценария отказа и без нарушенного правила | На усмотрение автора |

Повышение уровня требует доказательства, понижение — ссылки на документ, который допускает поведение.

## Шаблон

```markdown
# Ревью: <задача>

База: <sha или «рабочее дерево»> · Голова: <sha или время снимка> · Ревьюер: <агент или человек> · Дата: <дата>

## Вердикт
Можно сливать | Нужны изменения

## Спецификация
| Критерий | Статус | Доказательство |
| --- | --- | --- |
| <критерий> | выполнен / не выполнен / не проверяем | <тест или файл:строка> |

## Замечания
1. **<Блокер | Важно | Пожелание>** `<файл>:<строка>` — <что не так>.
   Сценарий: <вход> → <неверный результат> | Нарушено правило: <документ:строка>.
   Документ: <ссылка на ADR, AGENTS.md или навык>.

## Проверки
<команды и итог: npm run check, npm run check:docs, npm run agents:check>

## Передано
- security-reviewer: <что> | не нужно: <почему>
- privacy-specialist: <что> | не нужно: <почему>

## Открытые вопросы владельцу
- <вопрос со ссылкой на строки документов>
```

## Частые блокеры

Блокеры — нарушения [инвариантов](../../../../AGENTS.md#инварианты) и чек-листов «Проверки» профильных навыков. Отдельный список здесь не ведётся, чтобы не расходиться с ними.
