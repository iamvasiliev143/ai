# Архитектурные решения (ADR)

ADR фиксирует значимое решение: контекст, рассмотренные варианты, выбор и последствия. Оформление — по навыку `architecture-decisions`, правка документов — по `documentation`.

## Правила

- Файл `docs/adr/NNNN-краткое-имя.md`, номера подряд с `0001` без пропусков (проверяет `npm run check:docs`).
- Статусы: `proposed`, `accepted`, `superseded`, `deprecated`.
- Принятый ADR не переписывается. В старом меняется только статус на `superseded` и ссылка на замену либо добавляется строка «Уточнён: ADR NNNN» / «Частично заменён: ADR NNNN»; в новом — «Уточняет: NNNN» / «Заменяет: NNNN». Исправления опечаток и битых ссылок допустимы.
- Новый ADR сразу добавляется в индекс ниже.
- Новые зависимости, инфраструктура, внешние сервисы и MCP-серверы — только через ADR.

## Шаблон

```markdown
# NNNN. Краткое название решения

Статус: proposed
Дата: ГГГГ-ММ-ДД

## Контекст

Какая проблема, какие ограничения и требования; ссылки на документы.

## Варианты

1. Вариант A — плюсы, минусы, стоимость, риски.
2. Вариант B — …

## Решение

Что выбрано и почему.

## Последствия

Что меняется, что становится сложнее, какие проверки и документы нужно обновить.
```
